# 无线换网失败恢复修复（0.3.26）

用户报告切换到未配置的新 Wi-Fi 后，启动或首页“连接盒子”尝试旧网络并闪退。

## 根因和行为

Windows `.NET Runtime` 崩溃日志明确记录：BLE 状态返回盒子仍在使用的旧无线地址，后续 `ObserveHostKey` 抛出 `SetupException`。`ShellViewModel.Connect` 的异常过滤器没有包含这个类型，异常沿两个 async void UI 入口传播，导致进程退出。

连接边界现在接住 SetupException，并为其他蓝牙系统异常提供不含驱动内部信息的失败提示。无线地址恢复整体最多 30 秒，每个 SSH 探测最多 4 秒，不自动循环重试旧地址；没有可访问网络时返回需要配置 Wi-Fi 的状态。

已有无线配对的启动及首页连接失败后，显示“需要设置新的 Wi-Fi？”提示。用户可选择“设置 Wi-Fi”进入原盒子的无线向导，或“暂不连接”留在首页。手动停止及关闭主窗口不会再次弹出恢复窗口。恢复不清理配对、保存的网络、聊天或工作区，也不自动提交配网和初始化写入。

## 验证证据

- 修复前新增回归测试复现同一 SetupException，从启动辅助入口及首页共用连接方法逸出，2 项失败；修复后均通过。
- 覆盖取回地址仍不可达、主机身份不匹配、蓝牙 COM 异常、盒子未联网、用户取消、发现调用无响应时的总超时；失败后首页按钮和 Busy 状态恢复，配对文件及网关凭据保持不变。
- 当前电脑/盒子的真实网络条件下，使用原专用身份通过 BLE 查询旧网络地址，验证不可达时返回 `wifi_setup_required`，测试配对保持原样；未更换用户密码或修改真实配对。无线恢复测试组 14 项通过，1 项需要可达 Wi-Fi 的实机测试跳过。
- 自包含 EXE 的界面验收覆盖新提示框、取消后保留配对、确认后进入无线向导、手动停止不弹窗，以及已有连接及换板流程。
