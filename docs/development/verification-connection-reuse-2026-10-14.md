# 配置复用、端口回收与自动连接验证（2026-10-14）

版本：0.3.14，原主分支，完整 Windows x64 自包含便携包。

## 配置复用

插件部署在板子上，Windows 本机保存专用配对密钥和凭据。显式绑定仍需只读核验设备身份与环境；检查本身不等于重复配置。

安装器核验包中四个插件文件内容（统一 LF/CRLF），优先复用匹配的现有加载目录。相同 worker 凭据继续使用原文件和路径，保留有效超时及其他已有配置。代码、配置和凭据全部匹配时直接返回 reused，不生成插件目录或配置备份，不重写配置、不再次运行配置验证。换电脑的 worker 变化只更新绑定，保留代码和原 worker 文件；校验失败恢复原配置。内容不匹配时才创建新的插件版本目录。

聊天配置匹配时不重复写入；仅新增电脑公钥时只扩展对应的受限密钥，不改智能体配置。只有插件/加载设置或聊天配置变化才重启网关；单纯公钥、网关凭据导出无需重启，未运行的网关会启动。界面显示检查/复用/必要更新的实际状态。固定检查和配对程序仍通过私有临时目录传输，不把它视为重装插件。

新增 Python 6 项：重复绑定零配置写入/零备份/跳过验证、换电脑复用插件仅更换 worker、插件内容变化升级而不重复加载、更新失败恢复旧绑定、聊天配置重复零写入，以及新电脑仅扩展新密钥。

## 端口占用

实机确认 18790 的 ClawBox.Executor PID 31660 和 18889 的 SSH PID 25852 均来自已闪退的 APP PID 25604。清理前重新确认父进程不存在、二者路径对应 0.3.12 包/系统 OpenSSH，创建时间早于真实崩溃。只结束这两个旧残留进程，未结束当前 0.3.13 APP 或其他未知进程。端口已释放。

新版把自己启动的执行器和 SSH 加入匿名、不可继承的 Windows kill-on-close Job。显式关闭及 APP 进程结束时系统关闭 Job，回收其中进程；不接管或停止外部执行器。赋予失败时只清理本次新启动的进程。端口检查改为 loopback TCP 绑定探测，可识别非 HTTP 占用并提示具体端口和“无需重新绑定”。

新增桌面 8 项：真实进程加入 Job 后关闭句柄会结束该进程，另一个未加入的测试进程保持运行；非 HTTP 端口占用被识别且不关闭占用者；五组网关重启条件；持久配对在下一次启动自动尝试、失败返回引导、缺文件不连接。启动 Loaded 增加一次性标记，避免重复触发重连。已有连接使用密钥，不保存密码。

Job 行为依据：[Microsoft Job 限制](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information)、[进程加入 Job](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject)。未用实际用户 APP 崩溃测试替代正常工作进程；测试只操作自己创建的 loopback ping 子进程。
