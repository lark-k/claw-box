# 重启后连接恢复验证（2026-10-15）

版本：0.3.16，直接在原主分支修复，保留工作区中已有的 0.3.15 图标改动。

## 原故障与判断边界

用户反馈电脑突然重启后，连接引导显示“后台连接启动失败。请检查端口占用、配对密钥或盒子网关配置”，随后自行恢复。排查时本机 18790、18889 均无监听，原版完整连接诊断也已通过。没有捕获原故障时的子进程输出，不能确认当时是板子端旧 SSH 会话、网络恢复或其他故障；不能把此次故障认定为已证实的本机端口占用。

原程序将执行器与 SSH 的所有退出统一处理，丢弃了区分组件所需的信息。新版只识别固定错误类别，分别提示执行器数据目录锁、本机监听、SSH 认证、主机身份、网络和板子反向转发失败。原始子进程输出不写日志、不显示，不放入异常。

## 实现与回归

板子反向转发监听失败时，只关闭本次 APP 的失败 SSH 子进程，每 5 秒重试，最多额外尝试 12 次，累计等待 60 秒。执行器保留；取消会终止等待，其他失败立即返回。聊天健康检查与 SSH 反向转发成功确认必须同时通过。恢复不修改板子配置、不重新绑定、不发送聊天或重放文件任务。详细边界见 ADR 0011。

新增桌面回归 23 项，覆盖：各组件故障分类和输出脱敏、跨读取块的错误识别、暂时故障恢复、持续故障的次数/等待上限、取消、不可重试错误、真实子进程退出后读取诊断、失败隧道清理时执行器存活，以及聊天入口健康但反向转发未确认时拒绝提前成功。

`scripts/ci/Verify.ps1` 完整通过：构建零警告零错误；桌面 131 项通过、1 项可选身份实机测试跳过；执行器 63 项通过、1 项 AppContainer 环境测试跳过；插件 Node.js 11 项通过、板子 Python 31 项通过；状态迁移/修复与格式验证通过。
