# 第六阶段验收范围

目标：Windows 能在明确授权下读取文本、更新代码文本和操作 DOCX 文件，提供可被后续盒子连接适配器调用的协议。

## 验收

- 无凭据不能使用工具；worker 不能审批请求。
- 请求参数变化使审批失效；相同编号的重试不会再次执行写入。
- 文件访问不得越过配置目录，包括路径前缀混淆、junction 与 NTFS ADS。
- 文本覆盖要求当前 SHA-256，冲突保留原文件。
- Word 读取、新建、跨格式片段文字替换能够产生有效 DOCX，并保留源文件。
- 状态和审计持久化，重启不自动重放残留写入。
- 实际 HTTP 演示完成 file.write → file.read → word.create → word.replace → word.read。
- Release 编译、自动化测试和格式检查通过。

## 后续阶段

第七阶段：配对、可信连接和盒子工具注册，需要 Windows 主动连接盒子或经 SSH/TLS 的连接适配器。
第八阶段：桌面聊天窗口、审批展示、文件选择与进度界面。
第九阶段：故障注入、长时间运行、更新回退和安装签名验证。

首版不提供任意命令执行、控制正在打开的 Word 窗口、宏执行或 DOCX PDF 渲染。这些不应被当作已完成的能力。
