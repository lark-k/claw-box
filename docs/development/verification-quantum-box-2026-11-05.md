# Quantum 盒子实机阶段记录（2026-11-05）

## 2026-11-06：移除蓝牙模型备用和热点

按用户确认，蓝牙保留用于搜索、认证和 Wi-Fi 配置；模型对话只使用网络 SSH 隧道。热点入口与蓝牙模型传输的桌面和板端协议操作已移除。当前盒子更新板端服务前已备份原协议和 systemd 配置；更新后配网服务和模型网关均处于 active。临时身份经真实蓝牙加入后通过有线 SSH 模型隧道成功连接，并清理了临时身份。盒子 Wi-Fi 上另观察到已有 SSH 会话；新安装包在第二台电脑及跨 Wi-Fi 完整验收仍需另行进行。

## 2026-11-06：连接恢复与电脑热点

蓝牙备用通道增加已认证网络恢复，保留本机模型端口；网络恢复失败、成功、再次失效，以及正在回复时拒绝切换，已用自动化测试验证。Windows 开发机上只读验证了移动热点配置可读取。开发机连续两次未搜索到盒子，未完成此次功能的真实蓝牙到 Wi-Fi 切换，也未完成新电脑开启热点、盒子加入热点及模型对话的端到端实测。不能把自动化结果作为这两项实机验收。

后续新电脑热点实测：盒子完成 WPA 认证，但 DHCP 等待 45 秒后超时并恢复原网络。板端无线网卡抓包仅计数发现四个客户端 DHCP 数据包、未观察到服务端响应；该结果本身不能确定是 Windows 未发送还是无线链路丢失。关闭新电脑 TUN 后再次尝试仍发生 DHCP 超时，TUN 单独并非充分解释。测试时盒子的有线端口连接开发电脑并配置为 192.168.137.2/24；若热点也使用同一网段，还需排查重叠路由。

## 2026-11-06：蓝牙模型备用通道

在真实盒子上更新 BLE 服务并保留服务协议和 unit 的回滚备份。用临时电脑身份将 SSH 目标设为不可用的本机端口，验证网络连接失败后自动切换到蓝牙、本地模型列表检查和真实模型 SSE 对话；测试后撤销临时身份与令牌。该测试模拟了局域网路径不可达，并未替代新电脑及异地 Wi-Fi 的完整验收。桌面和板端另有协议边界、固定网关、失败不重放、同网络不重配及换网路径的自动化测试。

本次验证设备为现有 RK3568，旧配对及网络配置予以保留。盒子配置有两条默认路由；有线默认路由访问模型服务器超时，无线出口可用。模型网关在配置中优先选无线、其次尝试有线，仅在 TCP 建连期间选择出口，不在已发送请求后重放。

- 实际模型完成普通问答、SSE 流式输出及工具调用/结果往返。
- 两个独立客户端令牌均能访问模型，移除其中一个后另一个仍可用。

- 盒子 Python 蓝牙协议测试 34 项通过；盒子网关测试 12 项通过、其中 1 项 Windows 专属测试跳过。仓库 `scripts/ci/Verify.ps1` 通过；默认跳过的真实蓝牙与真实盒子桌面测试未运行。

备份在盒子 `/var/backups/quantum-harness/`，由安装和升级脚本分别建立。网关的上游凭据与客户端凭据仅存在盒子私有状态中。旧已登记 SSH 公钥没有被修改，其原转发策略不自动包含 18792；后续桌面连接需按新流程授权。

此阶段的旧安装包仍为占位界面，不能完成配对、隧道或自动模型配置。后续源码已接入桌面连接，安装版验收仍需独立完成；请勿将旧安装包作为支持盒子连接的新版本交付。

## 蓝牙稳定性与桌面连接基础（后续验证）

原始间隔为 1280 ms；连续扫描 45 秒首次在约 25.8 秒收到广播。临时调整到 100–150 ms 后，五次 10 秒扫描均发现盒子；持久化后又有六次 10 秒扫描中的五次发现盒子。蓝牙服务重启后内核读回预期间隔。Windows 原生发现实现连续三次搜索成功，首次 12 秒未发现时继续搜索 12 秒；不能据此保证所有环境均能发现。

两个临时身份分别经真实 BLE 加入并重连，保留各自独立模型凭据，测试后只清理临时身份。Windows 原生客户端使用原配对完成 BLE 认证和无线网络读取。另使用 BLE 新配对的临时身份验证了 Windows 原生模型隧道访问盒子模型接口；它绑定动态回环端口并核验 SSH 主机身份。以上均在同一台物理电脑上模拟两个身份，尚未完成两台物理电脑和新 Quantum 图形界面的验收。

Windows 原生连接组件也已实测：用新身份完成 BLE 认证、读取模型授权信息，再通过独立的 SSH 回环隧道访问模型列表；序列化配对结果不包含网关令牌。这些组件还未接入 Quantum Harness 的 Electron 界面和安装包。
