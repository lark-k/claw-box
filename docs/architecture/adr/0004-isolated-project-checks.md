# ADR 0004：代码项目构建与测试

状态：采纳。日期：2026-10-13。

维护者要求自然语言完成项目分析、代码修改和实际构建测试。增加 file.list 与 project.check，仍逐请求审批。file.list 返回受限源码清单及快照摘要；project.check 绑定路径、检查类型和相同源码摘要，源码变动必须重新请求。文件读取和修改继续使用现有审批接口与 SHA256 乐观并发检查。

构建和测试不在带管理员凭据的普通 Windows 进程中运行，也不要求 Docker。使用 Windows AppContainer 独立身份，零网络能力，清空继承环境，只提供源码快照、公开运行时和离线依赖缓存。进程挂入 kill-on-close Job Object 后才恢复执行，限制内存、进程数、时限与输出；创建失败不降级成普通宿主进程。模型不能选择可执行文件、环境、命令行或网络权限。

支持固定 build、test 两种检查，按 package.json、pom.xml、Gradle、csproj/sln 识别项目。已实测 Node、Vue、React、Java/Maven 与 .NET 构建；Gradle 适配为实验性，尚未实机验收。运行时在本机检测并记录于用户目录。非零退出代表检查失败；测试还必须观察到非零实际通过数量，全部跳过不能当作通过。构建只改快照，不回写原项目；代码编辑仍单独审批。网络隔离时新依赖需要预先安装/缓存，不能自动开放网络恢复。

每个构建记录摘要、模式、退出码与有界日志；错误和取消返回可核对结果，关闭或恢复不会自动重跑。取消信号和超时关闭 Job，结束本次进程树，再移除仅本次 SDK 读取授权及 AppContainer profile。仅传递指定的 stdin/stdout 句柄，不继承宿主凭据和其他句柄。公开 SDK 的临时读取 ACL 只授予本次隔离 SID，不授予私人用户目录。

隔离副本位于 ProgramData 下由 Windows 用户 SID 派生的私有目录；子目录授权当前用户与本次 AppContainer SID。Node/npm 和 Maven 拷贝到隔离目录。AppContainer 无法解析部分 DOS 卷规范路径时，Node 与 Java 适配器仅在指定隔离根或公开 JDK 内检查每个路径组件后返回规范绝对路径，拒绝链接，不改变 OS 实际读写权限，也不修改用户目录祖先 ACL。

Node 同步子进程捕获改用本次临时文件；内置 Node 测试运行于同一隔离进程。仅对副本中的精确 `vite build` 使用原生配置加载，esbuild 使用同步编译接口。Maven 离线执行并关闭 Surefire fork。Java 文件系统适配器来自程序集固定资源，先在宿主用 javac 编译这份固定模板，禁用注解处理；用户项目源码和插件全部在 AppContainer 内运行。这些兼容调整不回写原项目。

不是通用终端：不声明覆盖所有第三方框架、esbuild 插件、符号链接依赖布局、需要异步命名管道或联网/监听服务的集成测试。SDK 目录须允许当前用户授予临时只读访问；不能授权时检查失败，不提权。正常取消会清理临时授权，宿主被强制终止可能遗留临时目录、profile 与只读 SID 授权，崩溃后的自动清理属于后续稳定性工作；不得自动重跑项目。每种适配器须有明确验证记录，不能把已实现适配当作实测兼容所有项目。
