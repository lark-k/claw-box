# ADR 0020：官方 Harness 桌面与盒子模型网关

状态：新分支采纳，分阶段实现。日期：2026-11-03。

## 决策

根据用户在本次开发中的明确选择，方案 B 的智能体、会话、工具及工具权限使用官方 DeepSeek Harness，Windows 执行工具；盒子转发模型请求到自建服务器。此方案不继承旧执行器的逐请求精确审批及禁止通用 shell 的产品约束。官方工具仍受实际版本的权限与审批策略控制，不等于默认全权限。旧 WPF/OpenClaw 方案保留用于回退。

官方源码以 Git 子模块引入 `src/Quantum.Harness.Upstream`，固定提交 `ce7073d51254c26cd63b22a60835b8f948deb447`（0.2.2-alpha.2）。保留上游 LICENSE、第三方声明、锁文件与目录结构。Quantum 集成及品牌覆盖配方位于子模块之外；品牌脚本按固定提交生成源码与图标覆盖，生成记录用于拒绝覆盖未知本地改动。更新上游必须审查提交、同步固定版本并重新验证，不自动跟随 master。

## 运行与认证

客户端通过现有设备配对及认证 SSH 连接访问盒子回环地址上的模型网关。计划使用新端口 18792，与 OpenClaw 的 18789 分开。旧配对密钥只允许原端口转发，不能直接当作新端口已授权；盒子部署与 SSH permitopen 更新必须通过明确的后续安装流程完成。

网关固定上游服务器，仅允许 GET /v1/models 和 POST /v1/chat/completions；客户端凭据与服务器模型凭据分别管理，不转发客户端 Authorization。网关不执行工具、不跳转、不自动重试、不记录请求体和密钥。JSON 请求体按原始字节透传，响应按读取块立即转发，保留 SSE 工具参数分片；流中断不伪造 DONE。

模型上游优先 HTTPS。本轮用户提供的 HTTP 服务通过私有配置显式 allowHttp 进行开发验证；不代表具备公网加密。当前网关是开发原型，不包含服务器设备注册、额度计费、撤销轮换或硬件身份防克隆机制。

## 数据与回退

新运行数据在 `%LOCALAPPDATA%/QuantumHarnessNext`，DSH_HOME 与 Electron userData 分开于旧版 ClawBox 数据。网关上游凭据在运行网关设备的私有配置中；Windows Harness 只需要配对网关凭据。此轮本机联调将两者保存在本机私有目录，不提交仓库。尚未迁移旧聊天或安装替换旧程序。

本机开发网关仅用于验证链路，不代表请求已经过实体盒子。新配置默认模型为 Quantum Box。实体盒子安装、BLE/SSH 桌面集成、品牌改造、正式安装包和商业设备授权需继续实施与验收。用户当前无实体盒子，待提供 SSH 后实施盒子端部署。

## 验证

网关测试涵盖凭据隔离、来源限制、路由限制、HTTP 显式启用、响应错误脱敏和 SSE 实时转发。`scripts/dev/Test-ModelGateway.py` 对真实模型验证流式工具调用及工具结果往返；不会执行文件或 shell 工具。官方完整界面与模型循环需在完成上游安装构建后单独验收。
