# ADR 0011：重启后隧道建立失败的分类与有限恢复

状态：采纳。日期：2026-10-15。

电脑异常重启后，用户报告连接引导显示笼统的后台启动失败，随后自行恢复。排查时 Windows 两个本地监听端口空闲，原版完整连接诊断通过，未捕获原始失败时的 SSH 输出。因此不能确认是板子端旧会话、网络共享恢复还是其他暂时故障；界面必须按实际失败组件提示，不能将所有子进程退出归因于本地端口占用。

保留现有 loopback HTTP、受限 SSH 配对、端口与凭据边界。在内存中流式识别执行器和 SSH 的固定错误类别，不展示、保存或记录原始输出。每次读取最多 2048 字符，保留 128 字符片段用于跨块识别；未识别输出只给出该组件的通用提示。SSH 开启详细输出以确认反向工具转发成功；聊天健康检查和反向转发确认都通过才连接成功。

只有 SSH 明确报告 remote port forwarding failed 时，关闭本次失败的隧道进程，每隔 5 秒重建一次，最多额外尝试 12 次，总等待 60 秒，可由调用者取消。执行器保持运行，避免在等待期间重复启动恢复流程。故障持续时说明板子端转发监听未建立，提示旧会话、其他客户端和转发权限的可能性。本地端口占用、认证、主机身份、执行器数据目录锁与网络故障立即返回，不按远端端口故障重试。

恢复仅限连接建立阶段，不停止其他程序或板子进程，不修改板子 SSH 服务配置，不更换配对，不重放聊天、审批或文件任务。已建立连接断开仍按既有结果未知规则处理。启动诊断超时增加到 120 秒，以容纳有限恢复；不能保证超时前旧会话一定释放。
