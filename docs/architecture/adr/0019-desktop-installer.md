# ADR 0019：Quantum Harness 用户级安装与覆盖升级

状态：采纳。日期：2026-11-01。

在自包含便携包上增加 Inno Setup 7.1 安装程序，首期支持 Windows 11 x64。安装器以当前用户权限运行，在 Windows 已安装的应用中登记一个固定 AppId，并创建开始菜单入口及可选桌面快捷方式。不安装服务、计划任务或开机启动项，不安装开发 SDK，不自动更改系统组件、网络或板子配置。

默认安装根目录为 `%LOCALAPPDATA%\Programs\Quantum Harness`，程序放在 `versions/<版本>/`。每次升级先复制独立版本目录，再更新快捷方式与卸载登记。旧版组件不会混入新版目录。旧版本保留到卸载；这是磁盘空间与失败恢复可诊断性的取舍，不宣称提供应用数据迁移回滚。禁止降级，同版本可修复安装。若未来引入不兼容的数据格式变更，必须先另行设计备份和迁移。

2026-11-02 补充：首次安装显示路径选择页，允许当前用户可写的其他本地磁盘目录，拒绝磁盘根、UNC 和网络驱动器。APP 按自身目录定位执行器，数据仍使用原用户目录。升级自动带出原安装位置并拒绝直接换目录；迁移安装位置须先卸载、再选择新目录安装，避免一个 AppId 的卸载日志分散到多个目录。路径在交互向导和安装前分别校验，静默安装也不能绕过迁移限制。

2026-11-02 启动兼容性修正（0.3.28）：目标电脑 Windows 11 21H2 / 22000.1098 上，QuantumHarness 的 .NET 10.0.12 与两款 Dell 软件各自的 .NET 10.0.11 均报告 CLR 内部错误 0x80131506。能够确认目标 OS 不在当前 .NET 10 支持范围，不能仅凭同一错误码断言具体 CET 缺陷。安装最低技术基线提高到 Windows 11 24H2 / 26100，拒绝旧版时显示中文系统升级说明；支持仍以系统版本/版本类型处于微软支持周期并安装当前补丁为前提。当前不自动升级系统，不全局关闭防护，也不默认关闭应用 CET。新包是在安装前拦截不满足条件的系统，并不是对旧系统上的 CLR 崩溃已经完成修复或实机复验。

依据：[.NET 10 官方 OS 支持表](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md)、[Windows 11 生命周期](https://learn.microsoft.com/en-us/lifecycle/products/windows-11-home-and-pro)、[.NET CET 兼容性说明](https://learn.microsoft.com/en-us/dotnet/core/compatibility/interop/9.0/cet-support)。

2026-11-02 兼容包（0.3.29）：用户明确要求在不更新 Windows 的条件下尝试保持原功能。增加显式 `-LegacyWindows` 发布入口，只对该包的 x64 APP 与执行器 apphost 使用 `CETCompat=false`；标准发布显式保留 CET。兼容包针对 21H2 / 22000 起的系统，独立目录、ZIP、安装器和清单均带 legacy 标识，不替换标准产物。CET 关闭意味着这两个进程不默认启用该项硬件栈保护；不会修改系统全局安全设置或其他软件。运行时、业务代码、ACL、审批、loopback 和恢复规则保持一致，不把兼容包称作微软官方支持的旧系统运行环境。

兼容安装沿用原 AppId 和用户数据，版本子目录使用 `<版本>-legacy`，快捷方式和卸载记录指向相应目录；同版本切换标准/兼容包也不会把 DLL 混在一起。发布验证读取两个真实 EXE 的 PE 扩展 DLL 特征位，拒绝清单/构建模式/实际 CET 标志不一致的包。新增全新数据目录的真实首次启动检查，要求主窗口和连接方式向导出现且未建立连接；另外验证发布执行器的审批、文件与 DOCX 链路。当前开发机检查通过不代表目标 21H2 机器验收通过，后者需用户实机确认。

保持 `%LOCALAPPDATA%\ClawBox` 原有数据位置、ACL 和连接协议不变。同一用户的安装版接续便携版数据。卸载仅使用 Inno 的逐文件安装记录清理程序、快捷方式与登记，绝不递归清理安装根或 ClawBox 数据目录，用户放入版本目录的额外工作区文件也保留。不提供“一键清空数据”，防止默认工作区或自选工作区被误删；板子授权的撤销是独立设备维护操作。

安装与卸载检测现有 APP 的用户级互斥量（包括 0.3.26 便携版），要求用户等待任务结束并主动退出，不使用 Restart Manager 强制关闭。维护期间设置另一个互斥量，新 APP 在创建单实例互斥量后检查维护互斥量，避免安装中重启。旧便携版没有维护检查，用户仍需遵循退出提示。应用仍只清理自己拥有的后台进程。

本阶段没有应用内更新、联网版本检查、更新源、自动重放或板子自动升级。构建工具通过固定 SHA256 的便携 NuGet 重打包获取，不在仓库保存工具二进制。当前构建为未签名包；正式可信发布须接入发布者代码签名，并重建、验收安装器及卸载器。SHA256 仅用于完整性校验，不是发布者身份认证。

参考：[Inno Setup AppId](https://jrsoftware.org/ishelp/topic_setup_appid.htm)、[AppMutex](https://jrsoftware.org/ishelp/topic_setup_appmutex.htm)、[PrivilegesRequired](https://jrsoftware.org/ishelp/topic_setup_privilegesrequired.htm)、[便携编译工具包](https://www.nuget.org/packages/Tools.InnoSetup/7.1.0)。

2026-11-02 启动入口调整（0.3.30）：用户已确认兼容版能在目标电脑打开，要求双击后直接进入首页，连接方式由独立说明书指导。取消首次启动和启动自动重连失败时的自动弹窗，首页与设置中的手动连接、有线/无线向导、换板操作仍保留。已有完整配对继续后台尝试连接，失败仅保留状态提示；不更改配对、凭据和任务恢复规则。首次启动发布验收改为要求主窗口显示、无任何自动连接对话框。
