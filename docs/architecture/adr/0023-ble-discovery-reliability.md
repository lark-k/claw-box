# ADR 0023：提高盒子的蓝牙发现可靠性

状态：验证中。日期：2026-11-05。

现有 RK3568/BlueZ 5.66 的默认 LE 广播间隔为 1280 ms。Windows 实测连续扫描 45 秒，第 26 秒才首次收到盒子广播；应用当前一次扫描 12 秒，容易漏掉。测试性设置为 100–150 ms 后，五次连续 10 秒扫描均发现盒子；这是当前环境的结果，并不保证所有无线环境。

采用 BlueZ `[LE]` 的 `MinAdvertisementInterval=0x00a0` 和 `MaxAdvertisementInterval=0x00f0`，不变更服务 UUID、GATT 协议、配对及网络配置。该设置影响盒子控制器的传统 LE 广播；盒子接电运行，较高广播频率会增加无线电活动。部署须备份并保留既有 `main.conf`，如果该项已有明确的不同配置须停止而非覆盖，启动失败时恢复。需验证蓝牙服务重启后内核实际间隔、持续扫描和 GATT 认证；不能仅凭配置文件宣称有效。客户端发现应合并同一设备的广播及扫描响应，适当延长扫描与自动重试，不能根据广播名直接信任设备，最终仍验证签名和设备身份。

此参数由 BlueZ 加载为控制器默认参数，是否生效取决于内核管理接口；参见 [BlueZ 默认配置](https://github.com/bluez/bluez/blob/master/src/main.conf)。
